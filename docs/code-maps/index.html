1. Archify: service architecture

Open the architecture diagram → Interactive, self-contained HTML (pan, zoom, dark/light, export to PNG/SVG). It shows the path from the OpenShift Route through the gateway to web-app and the five API services, the internal calls between the Java services (role lookups and audit events), and the database role each service uses. Every box cites the source lines it is based on, verified against commit fb87092.

  • Source: archify/architecture-cwp-services/candidate.json (the diagram's data); Archify's validation receipts (*.json next to the HTML) stay local and are git-ignored, because they record absolute paths.
  • Automated checks passed (schema, layout, source evidence, real-browser rendering); not visually reviewed by a person.
  • Tool: tt-a1i/archify 3.2, installed as a Claude Code skill in ~/.claude/skills/archify.

2. Graphify: knowledge graph

Open the interactive graph → · collapsible tree · report (most-connected symbols, surprising connections, suggested questions) · graphify/graph.json (the full graph, queryable).

  • 1,718 nodes, 3,481 edges, 116 communities. Built from tree-sitter parsing only (no LLM), so communities are numbered, not named.
  • 81% of edges are EXTRACTED from the code; 19% are INFERRED by name matching and can be wrong (for example, a link from BpmnProperties.tsx to a Python test helper). Check inferred edges before relying on them.
  • Built from the committed code only, without docs/, lockfiles or build output.
  • Query it: graphify query "how does a task get completed" --graph docs/code-maps/graphify/graph.json, graphify path "TaskController" "HttpIdentityDirectory" --graph ....
  • Tool: Graphify-Labs/graphify (graphifyy 0.7.13 via uv tool; its /graphify skill was already installed).

3. CodeGraph: symbol index

Open the CodeGraph snapshot → Index statistics, every HTTP route it found (Spring, FastAPI and the SPA's React routes), and the callers of each cross-service seam: role lookups, the audit post, the writer() access checks and the SPA's apiFetch.

  • 200 files → 4,803 symbols, 9,723 edges, 78 routes, no parse errors. The index lives in .codegraph/ (SQLite, kept out of git) and stays in sync through a file watcher.
  • Claude Code uses it through the codegraph MCP server, registered for this project only (claude mcp get codegraph); start a new session to get its tools (codegraph_explore, callers, callees, ...). CLI: codegraph explore "role check", codegraph callers requireActive.
  • Tool: colbymchenry/codegraph 1.6.3 (npm i -g @colbymchenry/codegraph), telemetry off.

4. Regenerating

# CodeGraph (repo root)
codegraph sync && python3 -I docs/code-maps/codegraph/export.py .

# Graphify: build from committed code only, then copy the outputs here
tmp=$(mktemp -d) && git archive HEAD -- . ':!docs' ':!**/package-lock.json' ':!**/uv.lock' | tar -x -C "$tmp"
(cd "$tmp" && GRAPHIFY_BACKEND=none graphify update . && graphify tree --label CommonWorkflowPlatform)
cp "$tmp"/graphify-out/{GRAPH_REPORT.md,graph.html,graph.json,GRAPH_TREE.html} docs/code-maps/graphify/

# Archify: update the cited lines and the revision in candidate.json, then
ARCHIFY_UPDATE_CHECK_DISABLED=1 node ~/.claude/skills/archify/bin/archify.mjs finalize architecture \
  docs/code-maps/archify/architecture-cwp-services/candidate.json docs/code-maps/archify/cwp-services-architecture.html \
  --repo-root . --quality showcase --json
Keeping data local

Graphify can name communities and read docs with an LLM (graphify extract with a Gemini key), which sends file contents to Google. That was not done. If you want named communities, run it on the code export only (never on files holding credentials).
